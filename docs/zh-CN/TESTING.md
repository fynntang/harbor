## 复现检查

在仓库根目录执行：

```bash
sh scripts/check.sh
swift test --package-path apps/Harbor --scratch-path target/swift-harbor
./scripts/build_and_run.sh --verify
cargo run --locked -p harbor-cli -- --help
```

Rust 脚本检查格式但不改写文件，测试/Clippy/release 使用 `--locked`，失败立即退出。Cargo.lock 应与源码一起保留。`--verify` 还会重新构建/启动本 checkout 的 Harbor GUI，只检查进程存活，不验证可见交互。[CI](../../.github/workflows/ci.yml) 在 macOS 和 Ubuntu 运行 Rust 脚本，在 macOS 执行 Swift 测试和打包；本文不宣称远程 CI 已通过。平台测试有条件编译，Linux 数量不必等于 macOS。

## 仍需手工验收

破坏性/恢复检查应使用明确可丢弃的 Profile，真实登录由用户执行。生产账号数据不进入自动化夹具。

| 操作 | 观察内容 |
|---|---|
| 全新 clone | 新 bundle 和空数据，原版及既有 Profile 不受影响。 |
| 首次启动与重复启动 | 正确登录窗口，重复启动不新增实例。 |
| 关闭终端 / Harbor | 客户端保持独立运行。 |
| 停止或取消退出 | 正确客户端退出，或拒绝/超时保留 Profile 并阻止删除。 |
| 保留/删除数据 | 范围符合确认，明确的保留/废纸篓路径可恢复。 |
| 图标及窗口/菜单生命周期 | Dock/Finder/菜单显示、重启/缓存、关闭重开和 busy 控件。 |
| 多账号重启 | 各实例恢复正确账号和对话。 |
| OAuth / Browser / Computer Use | 实例路由正确，功能实际可用。 |
| Skills / MCP / 工具 | 记录共享/实例来源、PATH、SSH 和 Docker 行为。 |
| 版本变化 | 审查警告、启动拦截、单次例外及数据库兼容性。 |

不要公开完整客户端日志或把真实凭据复制进测试。`doctor` 不检查所有配置覆盖或账号身份，版本/冲突警告也可能不使其失败。接管 Profile 的回退可继续使用已验证的旧启动器和原路径；接管本身未迁移数据库或重签应用。不要把删除数据库、Singleton 文件或注册锁当作恢复捷径。删除后的恢复遵循[当前流程](GUI.md#removal-and-recovery)。
