# 路线图

[English](../ROADMAP.md) | 简体中文 · [文档目录](README.md)

Harbor 已在 macOS 平台发布。下一阶段里程碑是兼容 Windows，覆盖图形界面、CLI 和安装流程。这是后续计划；现有 macOS Intel 构建不能在 Windows 上运行。

## 下一阶段：Windows 支持

优先适配 Windows x64。最低 Windows 版本和是否纳入 ARM64，在核实官方客户端的架构与数据路径后确定。目前不设定发布日期。

| 步骤 | 工作内容 | 完成标准 |
|---|---|---|
| 1. 验证官方客户端 | 检查安装结构、应用身份、更新行为，以及独立数据目录的设置方式。 | 在 Windows 实机上运行两个实例，分别登录并在重启后保留各自账号，不改变原版账号数据；记录功能限制。 |
| 2. 适配核心与 CLI | 将 macOS/Unix 专用路径、权限、应用检查和进程操作与共用的实例逻辑分开，实现 Windows 下的创建、启动、停止、删除和副本更新。 | Windows CLI 测试通过；操作只作用于选定实例，拒绝或失败时保留数据；直接退出客户端后，能够识别并清理其残留辅助进程。 |
| 3. 增加 Windows GUI | 选择支持 Windows 的界面实现，保留现有 macOS 应用。提供实例管理、系统托盘、图标及英文/简体中文切换。 | 无需终端即可创建和管理实例；关闭窗口保留托盘入口，退出 Harbor 不结束客户端实例。 |
| 4. 打包与发布 | 增加 Windows CI、安装包和带校验的 Harbor 更新机制，确定签名与分发方式。 | 在干净的 Windows 环境测试安装、升级和卸载；Harbor 更新保留实例登记与数据，卸载时明确说明账号数据的处理方式；提供安装和恢复文档。 |

先验证客户端兼容性，再选择 GUI 框架和安装包格式。如果官方客户端无法可靠地使用独立数据目录，先解决这个问题，再推进 Windows 的其他功能。

## 发布验收

- 在 Windows 实机验证登录、重启、浏览器集成、残留进程和数据保留。仅编译成功或模拟测试通过，不算完成此里程碑。
- 保持 macOS 构建和测试通过。Windows 适配复用已有实例逻辑，避免无关地改变 macOS 行为。
- 在发行说明中列出支持的 Windows 版本、CPU 架构和客户端功能，明确标注尚未验证的功能。

具体实现记录在[架构说明](ARCHITECTURE.md)，已完成的检查记录在[测试记录](TESTING.md)。
